Sistema POS — Salsamentaria

Sistema de punto de venta web interno para gestión de ventas, pagos e inventario en tiempo real.

4

El sistema permite al cajero registrar ventas en tiempo real desde la PC del local, procesar pagos (efectivo, transferencia, tarjeta), generar facturas/recibos y controlar el inventario automáticamente tras cada venta.

Es un sistema de uso interno — no está expuesto al público. Acceso mediante login con roles diferenciados.

Laravel 10 MySQL 8 Blade + Bootstrap 5 PHP 8.2+ Uso local / LAN

Stack tecnológico

Arquitectura monolítica con Laravel MVC. Elección deliberada para un sistema de un único local: menor complejidad operacional, sin necesidad de API separada ni infraestructura distribuida.

Justificación de la arquitectura monolítica

Para un sistema de tienda local con 1–2 usuarios concurrentes, un monolito Laravel es la opción más pragmática. Evita la complejidad de mantener un backend API separado + frontend SPA cuando Blade renderiza las vistas desde el servidor con excelente rendimiento.

Si en el futuro se requiere una app móvil o múltiples sucursales, se puede evolucionar hacia una arquitectura API-first extrayendo los controladores en una capa de servicios separada.

Arquitectura del sistema

El sistema sigue el patrón MVC de Laravel con una capa de servicios adicional para aislar la lógica de negocio de los controladores.

Roles y permisos

Sistema de dos roles manejados con middleware de Laravel. Los roles se almacenan en la tabla usuarios.rol con valores admin / cajero.

ADMINISTRADOR
  • Gestión de productos y categorías
  • Gestión de usuarios y roles
  • Ver reportes de ventas e inventario
  • Exportar reportes a PDF / Excel
  • Configurar parámetros del sistema
  • Ver historial de facturas
  • Anular ventas (con justificación)
CAJERO
  • Registrar ventas en el POS
  • Buscar productos por nombre / código
  • Procesar pagos (efectivo, transferencia)
  • Generar e imprimir facturas
  • Ver stock disponible de productos
  • Sin acceso a reportes ni configuración
  • Sin acceso a gestión de usuarios

Flujo de una venta

Descripción del proceso completo desde que el cajero abre el POS hasta que se genera la factura. El paso más crítico es el paso 7: la venta y el descuento de inventario ocurren dentro de la misma transacción de base de datos.

01
Cajero abre el POS
Accede a /venta/nueva. Se crea un carrito vacío en sesión.
02
Búsqueda y selección de productos
Búsqueda AJAX por nombre o código. El resultado muestra nombre, precio y stock disponible.
03
Composición del carrito
El cajero agrega ítems y cantidades. El total se recalcula en tiempo real. Se valida que la cantidad no supere el stock.
04
Selección del método de pago
Efectivo: se ingresa el monto recibido y se muestra el cambio. Transferencia/tarjeta: se registra el número de referencia.
05
Confirmación
El cajero hace clic en "Cobrar". Se ejecuta la petición POST a /venta/procesar.
06
Validación en servidor
VentaController valida el request y llama a VentaService::procesar().
07 ⚡
Transacción atómica en base de datos
Dentro de DB::transaction(): crea registro en ventas, inserta detalle_venta por cada ítem, descuenta stock en productos.stock. Si algo falla, hace rollback completo.
08
Evento VentaCompletada
Se dispara el evento. El listener GenerarFactura crea el registro en facturas con número consecutivo.
09
Respuesta y factura
El cajero es redirigido a la vista de la factura generada. Puede imprimirla o descargarla como PDF.

Transacción atómica — implementación

// VentaService.php
public function procesar(array $carrito, array $pago): Venta
{
    return DB::transaction(function() use ($carrito, $pago) {
        $venta = Venta::create([
            'usuario_id'     => auth()->id(),
            'total'          => $carrito['total'],
            'metodo_pago'    => $pago['metodo'],
            'estado'         => 'completada',
        ]);

        foreach ($carrito['items'] as $item) {
            $venta->detalles()->create($item);

            // Descuento con lock para concurrencia
            Producto::lockForUpdate()->find($item['producto_id'])
                ->decrement('stock', $item['cantidad']);
        }

        event(new VentaCompletada($venta));
        return $venta;
    });
}

Seguridad

🔐
Autenticación
Laravel Sanctum con sesiones. Contraseñas con bcrypt (cost 12). Cierre de sesión automático tras 2h inactivo.
👤
Autorización por rol
Middleware CheckRole en rutas admin. Gates en acciones sensibles (anular ventas, ajustar stock).
🛡️
Validación de datos
Form Requests de Laravel para todas las entradas. Tipado estricto en migraciones.
🔒
CSRF Protection
Token CSRF de Laravel en todos los formularios. Protección por defecto en rutas web.
📦
Validación de inventario
Bloqueo a nivel DB (lockForUpdate) en descuento de stock. Evita condición de carrera en ventas simultáneas.
📋
Auditoría
Soft deletes en ventas y productos. Registro de usuario en cada venta. Historial de ajustes de inventario.

Instalación rápida

# Clonar e instalar dependencias
git clone https://github.com/tu-repo/pos-salsamentaria.git
cd pos-salsamentaria
composer install --no-dev --optimize-autoloader

# Configurar entorno
cp .env.example .env
php artisan key:generate

# Base de datos
php artisan migrate --seed     # Crea tablas + usuario admin inicial

# Permisos
chmod -R 775 storage bootstrap/cache

# Optimizar para producción
php artisan config:cache
php artisan route:cache
php artisan view:cache
